System architecture

Five layers: the web app, one FastAPI process with shared authentication, the loaded models, the data stores, and the offline Flower federation that writes the models the API serves.

Data flow diagram

Level 1. Patient rows stay in hospital partitions and the assessments log. Only counts go to the outbreak store, and only model updates or statistics leave a hospital during training.

Class diagram

Main classes and modules by objective: assessments, A, E, B, and the Flower app in C. Task modules share one interface that the server and client apps call.

%%{init: {'theme':'neutral'}}%%
classDiagram
  direction LR

  class FastAPIApp {
    +include_router(router)
    +create_ui_session()
    +revalidate_frontend()
  }
  class Security {
    +API_KEY: str
    +UI_SESSION_TOKEN: str
    +require_api_key(key, cookie)
  }
  class AssessmentIn {
    +age: int
    +gender: str
    +vitals: dict
    +symptoms: list
    +disease_id: str
    +confidence: float
    +atypical_flag: bool
    +novelty_flag: bool
    +severity_id: str
    +treatment: str
  }
  class SeverityIn {
    +severity_id: str
    +treatment: str
  }
  class AssessmentsRouter {
    +log_assessment(body)
    +set_severity(id, body)
    +list_assessments()
    +clinic_summary()
    -_day_counts(conn, day)
    -_push_summary(counts, day)
  }

  class AtypicalDetector {
    +p: dict
    +diseases: list
    +infer_disease(S, V)
    +score(df)
    +reasons(s_row, v_row, k)
    +assess(patient, disease_id)
    +assess_df(df)
  }
  class TreatmentRecommender {
    +success_model: XGBClassifier
    +recovery_model: XGBRegressor
    +feature_cols: list
    +candidates(disease, severity)
    +recommend(patient, disease, severity, top_k)
    +top_picks(df)
  }
  class DiseaseClassifier {
    <<XGBoost model + meta>>
    +predict(patient)
  }

  class NodeSummarizer {
    +hospital_id: str
    +region: str
    +detector: AtypicalDetector
    +summarize(df)
  }
  class Store {
    +path: Path
    +put_summaries(df)
    +load_summaries(as_of)
    +last_shared_day()
    +upsert_alert(alert)
    +resolve_stale(as_of, days)
    +list_alerts(status)
    +acknowledge(id)
  }
  class Panel {
    +hospitals: list
    +diseases: list
    +days: DatetimeIndex
    +n: ndarray
    +reported: ndarray
  }
  class Stats {
    +panel: Panel
    +p: dict
    +signals(p)
    +signature(h, k, t)
  }
  class OutbreakDetector {
    +p: dict
    +trained: bool
    +meta: dict
    +alerts_at(stats, signals, t)
    +scan_panel(panel, as_of)
    +trends(panel, as_of)
  }
  class Notifier {
    +notify(alert, change)
  }

  class FedXgbCyclic {
    <<Flower strategy>>
    +start(grid, initial_arrays, num_rounds)
  }
  class ServerApp {
    +main(grid, context)
    +collect_reference(grid, task)
    +stage_caller(grid, task)
  }
  class ClientApp {
    +train(msg, context)
    +evaluate(msg, context)
    +query(msg, context)
  }
  class NodeRegistry {
    +hospital_by_node: dict
    +from_env()
    +check_connected(node_ids)
    +check_complete(node_ids)
    +check_reply(sender, claimed)
  }
  class IdentityError
  class FederatedTask {
    <<interface: carepath_fl.tasks>>
    +MODELS
    +COLUMNS
    +fit_rows(df)
    +local_train(models, df, iters, seed)
    +local_evaluate(models, df)
    +client_stage(stage, state, df)
    +run_protocol(call)
    +write_model(models, meta)
  }
  class DiseaseTask
  class TreatmentTask
  class AtypicalTask
  class OutbreakTask
  class Deployment {
    +register_hospitals(hospitals)
    +start_hospitals(hospitals)
    +run_app(task)
    +online_nodes()
  }

Sequence diagram

One session: assess a patient, log the assessment and push counts to the outbreak store, then scan for outbreaks and acknowledge an alert.

%%{init: {'theme':'neutral'}}%%
sequenceDiagram
  autonumber
  actor C as Clinician
  participant UI as Browser (app.js)
  participant API as FastAPI + require_api_key
  participant E1 as Disease model (E1)
  participant A as AtypicalDetector (A)
  participant E2 as TreatmentRecommender (E2)
  participant AS as Assessments router
  participant DB1 as assessments.db
  participant DB2 as outbreak.db (Store)
  participant B as OutbreakDetector (B)
  participant W as Webhook

  rect rgb(232,240,254)
  Note over C,API: Session
  UI->>API: POST /ui/session (localhost only)
  API-->>UI: 204 + carepath_session cookie
  end

  rect rgb(230,244,234)
  Note over C,E2: Patient assessment
  C->>UI: Enter age, vitals, symptoms, submit
  UI->>API: POST /predict
  API->>E1: predict(patient)
  E1-->>API: disease and probability, alternatives
  API-->>UI: PredictOut
  UI->>API: POST /api/atypical/assess (patient, disease_id)
  API->>A: assess(patient, disease_id)
  A-->>UI: atypical_flag, novelty_flag, reasons
  C->>UI: Choose severity
  UI->>API: POST /recommend-treatment
  API->>E2: recommend(patient, disease, severity)
  E2-->>UI: ranked treatments, success prob, recovery days
  end

  rect rgb(255,244,224)
  Note over UI,DB2: Logging and surveillance sharing (counts only)
  UI->>API: POST /api/assessments (no patient name)
  API->>AS: log_assessment(body)
  AS->>DB1: INSERT assessment
  AS->>DB1: day counts per disease + ATYP
  AS->>DB2: put_summaries(hospital LIVE, day, counts)
  AS-->>UI: id, surveillance.shared
  end

  rect rgb(253,232,232)
  Note over C,W: Outbreak scan
  C->>UI: Open Outbreak surveillance, replay a day
  UI->>API: POST /api/outbreak/scan (as_of)
  API->>B: run_scan(store, detector, as_of)
  B->>DB2: load_summaries(as_of)
  DB2-->>B: node summaries from all hospitals
  B->>B: Panel, Stats, cross-site consensus
  B->>DB2: upsert_alert, resolve_stale
  opt new or escalated alert
    B->>W: POST alert
  end
  B-->>UI: alerts, new count, resolved
  C->>UI: Acknowledge alert
  UI->>API: POST /api/outbreak/alerts/id/ack
  API->>DB2: acknowledge(id)
  API-->>UI: updated alert
  end
